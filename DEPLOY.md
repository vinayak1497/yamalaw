# YamaLaw — Production Runbook

Live topology (free tiers):

```
Vercel (frontend SPA) ──HTTPS──> Render (Express API, free web service)
                                      │
                                      └──> Supabase Postgres (Mumbai, pooled 6543)
GitHub Actions cron (every 10 min) ──> /api/health  (keeps Render warm + Supabase active)
```

## Services

| Layer | Where | Project/service |
|---|---|---|
| Frontend | Vercel | `yamalaw` → `https://yamalaw.vercel.app` |
| Backend | Render | `yamalaw-backend` → `https://yamalaw-backend.onrender.com` |
| Database | Supabase | `yamalaw` (`upornmirfmznmxbzigkm`), region `ap-south-1` |
| Keep-alive | GitHub Actions | `.github/workflows/keep-alive.yml`, secret `RENDER_BACKEND_URL` |

## Environment (production)

Backend (Render → Environment):
- `APP_ENV=production`, `APP_NAME=YamaLaw`, `DEMO_MODE=true`
- `JWT_SECRET` — generated by Render (`generateValue` in `render.yaml`)
- `DATABASE_URL` — Supabase pooler:
  `postgresql://postgres.<ref>:<db-password>@aws-0-ap-south-1.pooler.supabase.com:6543/postgres`
- `CORS_ALLOWED_ORIGINS=https://<vercel-app>.vercel.app`
- `FRONTEND_URL=https://<vercel-app>.vercel.app`
- `AI_ENABLED=false` (Ollama is opt-in later)

Frontend (Vercel → Environment → Production):
- `VITE_API_URL=https://<render-backend>.onrender.com` (rebuild after changing)

## Deploy from scratch (all CLI)

```powershell
# 1. DB
supabase projects create yamalaw --org-id <org> --db-password <pw> --region ap-south-1
supabase link --project-ref <ref>
supabase db push --password <pw>   # applies supabase/migrations/* (boot DDL is a safety net)

# 2. Backend (repo must be pushed first — Render builds from GitHub)
render blueprints launch --file render.yaml   # or: dashboard → New → Blueprint → vinayak1497/yamalaw
# then set DATABASE_URL / CORS_ALLOWED_ORIGINS / FRONTEND_URL secrets

# 3. Frontend
cd frontend
vercel --prod --yes
vercel env add VITE_API_URL production   # paste Render URL
vercel --prod --yes                       # rebuild with API URL

# 4. Keep-alive
gh secret set RENDER_BACKEND_URL --body "https://<render-backend>.onrender.com"
# (workflow file is already in the repo; first scheduled run within 10 min)
```

## Notes / limits (free tiers)

- Render free sleeps after ~15 min idle; the cron keeps it warm. First request after a sleep can take ~60s.
- Render disk is ephemeral: uploaded files vanish on restart/redeploy. Demo + code unaffected (DB is remote). For durable files, a future step is Supabase Storage / MinIO.
- Supabase free pauses after 7 days without DB activity; `/api/health` runs `SELECT 1`, and the cron hits it every 10 min.
- Boot seeds reference data automatically if tables are empty; demo users/cases only when `DEMO_MODE=true` and no users exist. Reboots never duplicate.
- Logs: Render dashboard → service → Logs. Health: `GET /api/health` (public, includes `db: ok`).
